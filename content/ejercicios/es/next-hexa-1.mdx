# Next.js hexagonal: ejercicio 1

Ejercicio sencillo de arquitectura hexagonal utilizando Next.js +14 con app router y tailwindcss. Enfocado en frontend.

## Proceso

### 1. Estructura de la App
#### `npx create-next-app@latest`
- Inicializa la aplicación usando el comando de Next.js, usando la carpeta "src".
#### Estructura hexagonal
- Define las carpetas de una arquitectura hexagonal, en una carpeta llamada "core".
#### Creación de dominio y app
- Para esta aplicación tendremos que cumplir estas reglas:
  - Usuarios con: id (único, puedes generarlo con fecha + nombre), nombre, roleId (id que lo vincula a otra tabla con su rol, que puede no existir, lo que significaría que es un usuario normal), createdAt (marca de tiempo de creación) y updatedAt (marca de tiempo de edición).
  - Roles con: id (único, puedes generarlo con fecha + nombre), nombre (nombre del usuario), permissions (tipo de permiso, definido en un enum, con opciones: "ADMIN", "STUDENT", "STUDENT_PRO"), createdAt (marca de tiempo de creación) y updatedAt (marca de tiempo de edición).
  - Para este caso puedes usar tipos "string" para las fechas, ya que no usaremos persistencia para nuestro primer repositorio de infraestructura.
  - Para repositorios, necesitaremos definir funciones para "CRUD", en el caso de "Read", buscaremos por id y también todos en el caso de usuarios. En el caso de roles definiremos una función para devolver todos los "roles" con un permiso específico (por ejemplo, todos los administradores)

### 2. Usuarios
#### `InMemoryUserRepository`, "Create" user y "Read" users
- Crea `InMemoryUserRepository`, si aún no está hecho.
- En "actions", crearemos funciones para "Create" usuarios, usando SSR.
- En nuestra página, implementaremos un componente con un formulario para crear el usuario.
- Haremos lo mismo con "Read", que debería devolver todos los usuarios.

## Lo Que Aprenderás

- Fundamentos de arquitectura hexagonal
- Patrones de Next.js app router
- Buenas prácticas de TypeScript
- Principios de diseño guiado por dominio
